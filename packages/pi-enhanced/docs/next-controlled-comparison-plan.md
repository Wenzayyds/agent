## 任务与分组

| 任务 | 对照组 | 实验组 | 主要问题 |
| --- | --- | --- | --- |
| M：项目约定下的 normalizeKey 修复 | 把规则原文直接提供给模型，Memory/Context/Task 全关 | 同一规则作为 verified Memory；只开 Memory，只读搜索可用 | 搜索能否取回同等信息并完成修复，代价多少 |
| C：从长诊断输出定位数组校验缺陷 | Context 关闭；读取固定长报告后修复 validateItems | 只开 Context select 与工具输出管理；Memory/Task 全关 | 输出是否实际缩短，必要证据是否保留，修复是否受影响 |
| T：两文件导出修复与步骤计划 | 提供计划原文，Task/Memory/Context 全关 | 相同计划存入 Task，只开 Task 和只读 enhanced_task_get | 计划查询能否成功参与修复，与直接提供计划相比有何额外开销 |

M：用户目标和验收相同，规则正文在两组完全一致；区别仅为正文直接提供还是经 Memory 搜索获得。不能把缺少必要规则的失败当作 Memory 收益。规则用独立 fixture 编号和 hash 固定，包含与任务无关的干扰记忆；候选/归档记录不可见。

C：构造约 12,000 ASCII 字符的确定性诊断报告，两组读取相同文件、获得相同原始工具结果。实验组最大保留约 2,000 字符；离线验证关键定位信息仍可获取，且只改变模型请求视图、不改原始文件或工具结果关联。若未发生截断，标记未触发，不算 Context 效果。该任务测试工具输出管理，不宣称验证了长会话压缩或原生 Compaction。

T：计划内容、步骤顺序和验收要求完全一致。保留只读查询，不允许模型提计划、改状态、自动执行、恢复重放或写入 Memory。此轮只衡量计划访问功能，不代表已经证明完整 Task Manager 的崩溃恢复或状态机收益。Task 记录保留 draft 即可用于查询，不把它强行当作可自动注入的活动任务。

## 固定条件

统一使用 deepseek-flash、同一源码提交、固定 Docker 镜像、合成临时项目、相同每格预算和独立隐藏验证器。每格冷启动新的项目、Session 和存储，避免上一格记忆、任务状态或历史消息残留。每对预先固定执行顺序并记录，不根据结果挑选重跑。

文件工具仍仅 read/grep/find/ls/write/edit，全部进入无网、只读根容器。实验 M 额外允许 enhanced_memory_search，实验 T 额外允许 enhanced_task_get；其余组不开放这两个工具。模型网络经过现有硬预算网关，不允许宿主文件工具回退、Shell 或 MCP。

规则和计划本身属于输入信息，两组信息量与内容差异在报告中明确列出；不通过隐藏提示向实验组额外泄漏测试答案。

## 观测指标

每格同时记录：patchStatus、runStatus、独立隐藏测试、Patch hash、上游发起/完成请求数、网关拒绝与 requestOutcomes、实际输入/输出 Token、已确认费用、未知 usage 的费用预留上界、端到端耗时、Sandbox 审计。

模块指标：

- Memory：种子预检、查询原文（脱敏）、查询策略、命中 ID/数量、返回记录有效性；没有调用搜索则记为未激活。
- Context：实际配置、每轮前后估算 Token、removedMessages、truncatedToolResults、注入/跳过状态及理由；记录估算量和 Provider 实际用量各自的口径。
- Task：计划 ID/hash、查询调用与成功结果、计划实际触达；只证明模型收到计划，不凭模型自述认定计划发挥作用。

组间比较优先看隐藏测试与正常结束，其次看 Token、费用、请求数和耗时。补丁通过但预算停止，必须同时列出这两个事实。若两组都通过但实验组增加开销，也照实保留。6 次试验只能用于发现问题和评估继续实验的价值，不做统计显著性判断。

## 确认后的离线准备

以下准备已在本地实现并离线验证；远端 CI 通过前不能启动真实调用：

1. 将三类任务、相同信息的两组输入、隐藏测试与固定顺序写入版本化清单。
2. 为评测 Runner 添加 task-only 变体及内联规则/内联计划控制输入；不修改业务 Task Manager。
3. 为 Context 任务添加固定长报告和明确的工具输出配置；用 Stub 验证截断触发、必要证据可得、调用/结果关联完整。
4. 用本地 Stub 跑完六格，核对种子、工具白名单、模块触达、六格总预算和中途停止规则；重复 runId 必须拒绝。
5. 固定新 fixture/Runner 提交并完成回归及三平台 CI，再使用用户确认的预算执行一次。

上述准备通过前，即使用户认可预算，也不自动跳过离线验收。方案或预算需要变化时，先修订方案，不以现有 API Key 或历史授权替代本轮确认。

实现入口：controlled-cases.ts 固定六格、共享规则/计划和长报告；run-real-agent.ts 复用现有执行链；run-controlled.ts 串行调用原 Runner，持久化开始状态并拒绝重复 batchId，异常停止后续格。所有受控实验禁用 Pi/Provider 自动重试。真实执行前核对同一源码提交的三平台 CI 证据。
